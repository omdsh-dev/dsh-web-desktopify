# 内容寻址构建 DAG

打包链四步（deploy 闭包 → SEA 后端 → 壳二进制 → 平台组装）需要增量复用，
避免每次全量重建。每步产物按输入指纹内容寻址存放于
`cache/<digest>/`，命中检查只关心目录在不在（不比对状态记录）；
依赖传导由 digest 链保证——依赖步重建后其指纹变化，下游必然重建。
`--force` 全部重建；构建先落 `build/<uuid>/` 暂存，完成后原子 mv 进 cache。
digest 是含依赖链的完整输入指纹（sha256），不同步产物碰撞概率可忽略，
无需按步分目录；步与 digest 的对应关系由状态记录（build-<ts>.json）承担。
