# SEA 薄入口 + 外置闭包

SEA blob 内模块的 `import()` 受 SEA 限制，无法解析外部依赖；把全部依赖
内联进 blob 又让打包复杂且脆弱。因此 blob 内只留 node builtin 导入的
`sea-entry.mjs`，dsh CLI 与全部依赖经闭包内 CJS 桥 `dsh-bridge` 从可执行
文件旁的 node_modules 走正常 Node ESM loader 解析——依赖闭包、原生模块
（Node-API addon）与顶层 await 均不经过 SEA blob，产物校验不含未内联的
ESM 裸导入。

桥必须显式调用 dsh CLI 入口导出的 `runCli()`：`lib/bin.js` 以
`if (import.meta.main) await runCli()` 自启动，而 `import.meta.main` 只对
程序入口模块为真，经桥动态 `import()` 的模块恒为 false——CLI 会静默退出
（exit 0、零输出），壳解析不到 `dsh web:` 就绪行而无限重启后端、窗口停在
启动页。这条依赖 dsh 的入口导出，升级 dsh 后需回归验证。
